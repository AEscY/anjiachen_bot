三、保留的核心教训（每条对应旧版真实 bug）
═══════════════════════════════════════════════════════════

1. 只在【完全成交】时记账
   旧版部分成交时按整单成本平摊：买入 10 卖 3，
   赚 6U 记成亏 694U，剩余 7 个币凭空消失。
   本版只在 status=='closed' 时处理。

2. 订单状态以交易所为准
   每轮对比本地记录与交易所未成交列表，不依赖回调。

3. 权益口径唯一
   不做 cap，不缩放。旧版 cap 与真实权益混用，
   回撤算成 99.99%，永久熔断且无日志。

4. 每档金额单一实现
   挂单与 /status 调用同一个 per_grid()。
   旧版两处各算一遍：报告说 3.60U「会挂单」，
   实际挂 12070U（超额 14.5 倍）。

5. 不用 getattr 兜底
   参数名写错就崩。Params.get() 对未登记的名字抛 KeyError。

6. 风控只管开新仓，不管记账和止损
   【本版端到端测试新发现，见第六节】

7. 卖单跟随（防死挂）
   单边下跌时卖单价锁死在现价上方十几 percent，
   永远成交不了，买单却在下方继续吃货。
   实测：center=100 s=2% 成本98.04 现价90
        不跟随：卖 100.00，需涨 11.1%   ❌ 死挂
        跟随：  卖  92.16，需涨  2.4%   ✅ 可成交
   三条约束：老化 24h + 浮亏超 1.5 倍间距 + 最多让利 6%

8. resume 必须重置回撤峰值
   否则 peak_equity 是历史最高，账户跌下去后回撤恒超标，
   resume 每轮都被拦，用户永远恢复不了。

9. 日志脱敏挂 handler 不挂 logger
   挂 logger 时子 logger 的记录走传播，根本不过滤。

10. 行情与交易用两个实例
    ccxt sandbox 会整体切换 urls，无法保证行情真实。

六、本次重写过程中发现并修复的缺陷
═══════════════════════════════════════════════════════════

【最严重】风控暂停时把成交记账也停了

    原写法：
        if not risk.can_open(equity):
            return              ← 整个循环跳过

    后果（端到端测试实测）：
        交易所持仓 8.2422，本地账本 0.0000
        买单在交易所成交了，本地完全不知道
        → 账本与交易所不一致
        → 重启即触发对账告警
        → 且这些持仓不受任何止损保护

    这与旧版 v20「熔断把止损也停了」是同一类错误：
    保护措施反而制造了更危险的状态。

    修复：分层
        ① 成交记账 —— 永远执行
        ② 区间止损 —— 永远执行（保护优先于暂停）
        ③ 开新仓   —— 受风控控制

    修复后实测（下跌 300 轮）：
        成交笔数 2 → 4
        账本差异  8.24 → 0.00

【致命】commands.py 用了 asyncio 却没导入
    pyflakes 静态检查发现。启动时必崩。
    已修复，并把 pyflakes 零告警纳入验收标准。

【设计缺陷】resume 不重置回撤峰值 → 永久停摆
    已修复：resume(equity) 重置 peak 与日基准。

八、已知限制（刻意不做）
═══════════════════════════════════════════════════════════

  · 无回测 —— 改参数只能实盘验证

建议每周手动发一次 /backup，或要求补上定时推送。

十一、v2：交易所致命错误分类（真实部署日志暴露）
═══════════════════════════════════════════════════════════

部署后出现：
    okx {"msg":"APIKey does not match current environment.","code":"50101"}
    SOL/USDT 取不到价格，跳过
每 10 秒一行，永不停止。机器人"活着"，但什么都没做。

【缺陷 1】公开行情实例误带密钥（代码 bug）

    def _make(sandbox):
        ex = cls({"apiKey": C.API_KEY, ...})   # ← pub 也带上了
    self.pub = _make(False)

公开行情接口本就不需要认证。带上密钥后交易所会去校验它 ——
模拟盘 key 请求真实域名就返回 50101，连最基础的取价都被卡死。
文档字符串明明写着"pub —— 行情用，永远真实"，代码却把密钥也塞进去了。

修复：pub = _make(False, with_auth=False)

【缺陷 2】永久错误被当成临时错误

原写法：所有异常一律 except → warning → 返回空值 → 下轮重试。
但 key 配错是【永久】错误，重试一万次也不会好。
后果：日志刷屏、浪费额度，而 Telegram 是唯一通知渠道，用户完全不知情。

修复：错误分两类
    fatal     —— AuthenticationError / PermissionDenied / 50101 等码
    transient —— 网络超时、限频、交易所不可用（正常重试）

fatal 的处理：
    · 立刻同步推送用户（含具体修法）
    · 只推一次，不重复打扰
    · 只请求一次，后续快速返回空（不刷屏）
    · 所有交易动作安全返回空，绝不带着错误状态下单

【为什么用同步推送】

Exchange 在 TradingBot.__init__ 里构造，那时还没有事件循环，
async 的 _tell() 用不了（get_running_loop 会抛 RuntimeError）。
结果是：最该送达的告警反而送不出去。
所以新增 notify.py —— 用 urllib 直接调 Telegram API，
不引入新依赖，任何时机都能发，失败只记日志不影响启动。

【本轮教训：假守卫】

第一版测试这么写：
    pub = exchange._make(False, with_auth=False)
    assert not pub.apiKey
然后把 bug 改回去验证守卫 —— 测试【依然通过】。
因为它测的是函数本身，不是 __init__ 里实际怎么调用。
__init__ 写成 _make(False, with_auth=True) 时，
测试调的还是 _make(False, with_auth=False)，当然通过。

修正：检查真实构造出来的实例
    exchange.Exchange._load_markets = lambda self: {}
    real = exchange.Exchange()
    assert not real.pub.apiKey
重新验证：改回 bug → 3 项失败；还原 → 80 项全绿。守卫这才算真的有效。

═══════════════════════════════════════════════════════════
十二、v3：权益口径漏算挂单冻结资金（真实部署暴露）
═══════════════════════════════════════════════════════════

用户部署日志：
    日基准权益 7256.38U
    SOL/USDT 挂买单 档0 9.625416@99.83
    ... 共 4 档，每档 960.91U
    风控拦截：日亏损 52.97% 达上限 5%，暂停 1 小时
    冷却中（剩 59/60 分钟）… 每小时重复

【根因】ccxt 的 free 不含挂单冻结的 USDT

数字完全吻合：
    日基准 7256.38 = 可用 4805.53 + 1 ETH 2450.85
    挂 4 档 × 960.91U = 冻结 3843.64U
    权益(错误) = (4805.53-3843.64) + 2450.85 = 3412.74
    日亏损 = (7256.38-3412.74)/7256.38 = 52.97%   ← 与日志一致

钱还在账户里（在 used 里），只是暂时锁定在订单中。

【后果：死循环】

    网格挂单 → 冻结 3843U → 权益"蒸发" 53%
      → 触发日亏损 5% → 暂停 1 小时
      → 订单还挂着，1 小时后重算，仍是 53%
      → 再次暂停 → 永久停摆

    即：网格越正常工作，越容易把自己熔断。

【修复】equity = 可用 + 冻结 + 持仓市值

    balances() 返回 (free, used, coins) 三元组
    部分交易所不给 used → 用 total - free 兜底
    per_grid() 仍用 free（冻结的钱不能重复挂单）

    /status 现在显示：
        权益      7256.38U
          可用    4805.53U
          冻结    3843.64U（挂在订单里，不是亏损）
          持仓    2450.85U

【顺带修的两个】

1. 买入/卖出/止损通知全部静默丢失
   _on_fill / _liquidate 是同步函数，里面写 self._tell(...)
   只创建协程却没人 await → 通知丢失，日志只留一行
       RuntimeWarning: coroutine '_tell' was never awaited
   改成 _tell_nowait()。这三类恰恰是最该收到的通知。

2. 重新部署时 "Task was destroyed but it is pending"
   主循环用 while True + asyncio.sleep，收到 SIGTERM 时被销毁。
   改成 asyncio.Event，post_stop 里请求停止并保存状态。
