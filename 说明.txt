一、为什么重写
═══════════════════════════════════════════════════════════

旧版的客观指标：

    bot.py          4868 行，137 个方法
    超 100 行的方法  8 个
    "原实现"补丁注释 64 处
    try/except      88 处（仅 bot.py）
    getattr 兜底    84 处（仅 bot.py）

64 处"原实现"是补丁叠加的直接证据：每发现一个问题就
在旁边加一层，而不是把错的改对。

最讽刺的一点：那 84 处 getattr 兜底，加的理由是
"参数名写错也不会崩"。结果 v23 的 equity_cap 拼写错误，
正因为不会崩，才静默溜到线上 —— 三个币种全部报错，
用户截图才知道。

    保护变成了掩盖。

三、保留的核心教训（每条对应旧版真实 bug）
═══════════════════════════════════════════════════════════

1. 只在【完全成交】时记账
   旧版部分成交时按整单成本平摊：买入 10 卖 3，
   赚 6U 记成亏 694U，剩余 7 个币凭空消失。
   本版只在 status=='closed' 时处理。

2. 订单状态以交易所为准
   每轮对比本地记录与交易所未成交列表，不依赖回调。

3. 权益口径唯一
   不做 cap，不缩放。旧版 cap 与真实权益混用，
   回撤算成 99.99%，永久熔断且无日志。

4. 每档金额单一实现
   挂单与 /status 调用同一个 per_grid()。
   旧版两处各算一遍：报告说 3.60U「会挂单」，
   实际挂 12070U（超额 14.5 倍）。

5. 不用 getattr 兜底
   参数名写错就崩。Params.get() 对未登记的名字抛 KeyError。

6. 风控只管开新仓，不管记账和止损
   【本版端到端测试新发现，见第六节】

7. 卖单跟随（防死挂）
   单边下跌时卖单价锁死在现价上方十几 percent，
   永远成交不了，买单却在下方继续吃货。
   实测：center=100 s=2% 成本98.04 现价90
        不跟随：卖 100.00，需涨 11.1%   ❌ 死挂
        跟随：  卖  92.16，需涨  2.4%   ✅ 可成交
   三条约束：老化 24h + 浮亏超 1.5 倍间距 + 最多让利 6%

8. resume 必须重置回撤峰值
   否则 peak_equity 是历史最高，账户跌下去后回撤恒超标，
   resume 每轮都被拦，用户永远恢复不了。

9. 日志脱敏挂 handler 不挂 logger
   挂 logger 时子 logger 的记录走传播，根本不过滤。

10. 行情与交易用两个实例
    ccxt sandbox 会整体切换 urls，无法保证行情真实。

2. Procfile 的作用（双保险）

    内容只有一行：

        web: python main.py

    旧版入口是 app.py，新版是 main.py。
    如果你忘了改 Render 后台的 Start Command，
    Render 会自动用 Procfile —— 避免部署失败。

    仍然建议手动确认：
        Render → Settings → Start Command
        改成：python main.py

    TG_CHAT_ID        必填

       退出并打印"缺少环境变量: XXX"。

六、本次重写过程中发现并修复的缺陷
═══════════════════════════════════════════════════════════

【最严重】风控暂停时把成交记账也停了

    原写法：
        if not risk.can_open(equity):
            return              ← 整个循环跳过

    后果（端到端测试实测）：
        交易所持仓 8.2422，本地账本 0.0000
        买单在交易所成交了，本地完全不知道
        → 账本与交易所不一致
        → 重启即触发对账告警
        → 且这些持仓不受任何止损保护

    这与旧版 v20「熔断把止损也停了」是同一类错误：
    保护措施反而制造了更危险的状态。

    修复：分层
        ① 成交记账 —— 永远执行
        ② 区间止损 —— 永远执行（保护优先于暂停）
        ③ 开新仓   —— 受风控控制

    修复后实测（下跌 300 轮）：
        成交笔数 2 → 4
        账本差异  8.24 → 0.00

【致命】commands.py 用了 asyncio 却没导入
    pyflakes 静态检查发现。启动时必崩。
    已修复，并把 pyflakes 零告警纳入验收标准。

【设计缺陷】resume 不重置回撤峰值 → 永久停摆
    已修复：resume(equity) 重置 peak 与日基准。

八、已知限制（刻意不做）
═══════════════════════════════════════════════════════════

  · 无回测 —— 改参数只能实盘验证
  · 无静默检测 —— 机器人卡住不会自动告诉你
  · 无趋势过滤 —— 单边下跌靠区间止损硬扛
  · 无 WebSocket —— 10 秒轮询，不适合高频
  · 只有网格一种模式
  · 无自动备份 —— 只有手动 /backup

这些都可以后续加，但每加一个都要重新跑端到端回环。
本版的立场是：宁可功能少，不要不可靠。

关于自动备份：Render 免费层磁盘不持久，重启必丢状态。
建议每周手动发一次 /backup，或要求补上定时推送。
